# План RepairCalc: MVP и развитие

## Кратко

Собрать демонстрационный микросервис в закрытом контуре: Rust отвечает за REST API и расчёты, Python — за ML-подбор и локальную LLM через Ollama, Vue 3 — за интерфейс калькулятора. Сначала подтвердить доступ к каталогу и договориться о формате обмена между сервисами, затем реализовать обязательные сценарии ТЗ.

## Этапы работ

1. Подготовка данных и контрактов. Проверить доступность API каталога, получить тестовую выборку и выяснить правила региональных цен и наличия. Загрузчик должен проходить страницы до last_page, получать полные карточки там, где нужны характеристики, и объединять товары по id. Согласовать JSON-контракты Rust API и Python-сервиса.
2. MVP расчётов и рекомендаций. В Rust реализовать общий расчёт сметы по типу объекта, ремонту и параметрам комнат; расчёт количества и стоимости товара по его id и размерам; фильтрацию рекомендаций по назначению комнаты, влажности и нагрузке. В Python реализовать ML-матчинг товаров к категориям работ на подвыборке и ранжирование подходящих товаров. Цены брать из result_price, учитывать единицу продажи и размер упаковки.
3. Интерфейс и демонстрация. Собрать Vue 3-виджет для сценария «квартира → капитальный ремонт → санузел» и для расчёта товара по размерам. Подготовить Docker-запуск сервисов и демонстрационные данные. Проверить полный сценарий от ввода параметров до сметы с товарами и итоговой стоимостью.
4. После хакатона. Добавить RAG-пояснения на локальной модели Ollama и базу знаний норм расхода; затем — мини-админку с подтверждением ML-привязок, хранение данных и метрик, обучение поправок расхода по заказам. CV по планам помещений оставить отдельным исследовательским этапом: в MVP он не входит.

## Интерфейсы и критерии приёмки

- Внешний API: POST /api/v1/estimate для сметы по объекту и комнатам; POST /api/v1/product/{id}/calc для расчёта товара по размерам.
- Внутренний API Python-сервиса: классификация товара и получение ранжированных кандидатов; Rust передаёт контекст комнаты и получает результаты с оценками.
- Результат сметы содержит позиции с товаром, количеством, упаковками, единицей продажи, ценой за единицу и суммой, а также общий итог.
- Демосценарии: квартира с капитальным ремонтом и санузлом с высокой влажностью; расчёт количества и цены товара для заданного размера стены.
- Качество матчинга оценивать на размеченной подвыборке, целевой ориентир ТЗ — F1 не ниже 0,8 на приоритетных категориях. Также сверить расчёты с эталонными примерами.

## Допущения

- Для быстрого MVP используется выбранное разделение: Rust API, Python ML/LLM и Vue 3; запуск — в Docker.
- LLM работает локально через Ollama; подключение внешних LLM API не закладывается.
- RAG и админка относятся к развитию после MVP, если на них не останется времени в рамках хакатона.
- Доступ, региональные правила каталога и фактический формат ответов стенда нужно подтвердить в начале работ; в markup.md описаны структуры и ограничения, но примеры ответов там иллюстративные.
